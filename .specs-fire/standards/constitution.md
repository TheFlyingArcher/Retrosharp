# Project Constitution

> Universal policies that apply to ALL code in this project.
> This file is always inherited from root — modules cannot override it.
> Source of truth for repo rules: `AGENTS.md` and `.github/pull_request_template.md`.

## Git Workflow

- **Commit Style**: Clear, concise messages; subject line under 75 characters
- **Branch Strategy**: Descriptively named feature branches merged via pull request
- **Main Branch**: `main` is branch protected and always deployable. **Never push to `main`.**

## Code Review

- All changes go through a PR from a feature branch, following `.github/pull_request_template.md`
- No self-merging to main
- Security-sensitive changes require additional review

## CI/CD

- No CI workflows are configured yet (`.github/workflows` absent); tests are run locally before opening a PR
- Deployment is Docker Compose based (see `docs/deployment.md`), including a Raspberry Pi (ARM64) target

## Security Policies

- **No secrets in code** — configuration comes from `.env` (git-ignored); `.env.example` documents the keys
- No credentials, API keys, or tokens in source control
- Phase 1 API is anonymous by design; auth/SSO arrives in Phase 2 (`spec/api.md`)

## Documentation

- Specs live in `spec/`; architecture in `docs/architecture.md`
- Specs are AIDLC learning artifacts: drift is expected, and the code is the source of truth
- Keep the README current with setup instructions
